# タイミング外しピッチャー

少年野球（学童軟式・小6）の投手が、投球動作の「間（ま）」を変えて打者のタイミングをずらす練習をする Web アプリ。
姉妹アプリ「三塁コーチャー判断トレーナー」と同じ作り（Vite + React + TypeScript、ロジックと UI の分離、端末内保存、ログインなし）。

## 使い方

```bash
npm install
npm run dev      # http://localhost:5173 を開く
npm test         # ユニットテスト＋キャリブレーションテスト
npm run build    # dist/ に出力（PWA。一度開けばオフラインで動く）
```

## どこを直せばいいか

| 直したいもの | ファイル |
|---|---|
| 打者・走者の強さ、区間の目安、ルールの閾値などの数値 | `src/sim/constants.ts` |
| ステージ・「リベンジ」の場面（アウト・ランナー・点差・カウント・打順） | `src/game/stages.ts` |
| 子ども向けの文言・監督のひとこと・入門の文章 | `src/game/messages.ts` |
| 練習パターンのプリセット・組み立て練習の順番 | `src/practice/presets.ts` |
| 計測チャレンジの採点の幅 | `src/practice/score.ts` |

**`src/sim/constants.ts` の数値を変えたら、必ず `npm test` を通すこと。** キャリブレーションテスト（`src/sim/__tests__/calibration.test.ts`）が、仕様書 §10 の「体感として正しい挙動」を 3,000 打席のシミュレーションで確かめている。

## 構成

```
src/
  types.ts        データの形（仕様書 §8）
  sim/            シミュレーション。純粋関数のみ・UI に依存しない
    constants.ts  数値はすべてここ
    rng.ts        シード付き乱数（mulberry32）
    timing.ts     区間の計算、ボーク・ルール判定
    batter.ts     打者モデル（予想 → タイミング誤差 → 結果）
    runner.ts     走者・牽制モデル
    atBat.ts      打席・イニングの進行（1球ごとに 状態＋投球 → 新しい状態＋記録）
  game/           ステージ・文言・ランク／バッジ
  audio/cues.ts   合図音（Web Audio で AudioContext.currentTime に予約）と効果音
  practice/       モード2のロジック（計測・採点・プリセット）
  storage/        localStorage（キー `pitcherTiming:v1:<ニックネーム>`）と JSON 書き出し／読み込み
  ui/             画面
```

## キャリブレーションの結果（§10）

| # | 確かめること | 目標 | 結果 |
|---|---|---|---|
| 1 | 強打者に「ふつう」5球、4球目以降のジャスト率 | 60%以上 | 85% |
| 2 | 強打者に毎球2区間以上を変える → 打ち取り率 | 55%以上 | 70% |
| 3 | まっすぐ待ちに1区間だけ変える → 打ち取り率 | 60%以上 | 78%（いつもふつうだと 47%） |
| 4 | S3 を0.6秒ためたときのジャスト時の長打率 | はっきり上がる | +23ポイント（強打者 40% → 63%） |
| 5 | 盗塁成功率：S1 いつも同じ／ばらつかせる | 70%以上／40%以下 | 89%／35% |
| 6 | ボス：でたらめ／直前と大きく変える → 打ち取り率 | 30%未満／50%以上 | 28%／65% |
| 7 | ボーク・二段モーション注意・遅延の判定 | 出る | ○ |
| 8 | 同じシードと入力で同じ結果 | 同じ | ○ |

ステージごとのクリア率（2,000 回のシミュレーション。投げ方の方針別）：

| ステージ | いつもふつう | でたらめ | 毎球2区間以上変える | 直前と大きく変える |
|---|---|---|---|---|
| 1 練習試合 | 58% | 98% | 99% | 99% |
| 2 地区大会 | 59% | 97% | 97% | 99% |
| 3 準決勝 | 48% | 96% | 98% | 99% |
| 4 決勝 | 25% | 84% | 88% | 95% |
| 5 リベンジ | 13% | 48% | 53% | 77% |

（上の表は、コースをねらわずに投げたときの値。コースの影響の目安：ボスにリズム「ふつう」のまま投げると、ど真ん中 7%、ストライクゾーン内でたらめ 13%、外角低め（苦手）30%。「直前と大きく変える」リズムなら、ど真ん中 59%、外角低め 70%）

## 仕様書から変えた・足したところ

| 項目 | 仕様書 | 実装 | 理由 |
|---|---|---|---|
| 打者の「見て合わせられる幅」（`adjust`） | なし | 予想とのずれがこの幅（強打者 0.10秒、ボス 0.38秒）におさまれば、打者は合わせてしまう | 指数移動平均だけだと、ボスが「でたらめ」に投げても 57% 打ち取れてしまい、§10-6（30%未満）を満たせなかった。この幅を入れると「強打者は少しの変化なら合わせる」「ボスは直前と大きく変えないと崩れない」が自然に出る |
| 打者タイプの得意・苦手（`earlyGain` / `lateGain`） | 「せっかちは S3 のために弱い」「じっくり型はクイックに弱い」→ じっくり型は「すぐ」に弱い、に読み替え | 予想より遅い球／速い球に対するずれの倍率で表した | 1つの数字で直せるように |
| ボスは長いセットで力まない | じっくり型だけ力まない | ボスも力まない | 長く止まるだけでボスのばらつきが増え、でたらめでも打ち取れてしまうため |
| ずらしの要素とカード | とまる・あしあげ・ため 各3段階 | とまる（3段階）・あしあげの速さ（クイック 0.2 ／ふつう 0.42 ／ゆっくり 0.7秒）・ため（すぐ 0 ／ふつう 0.12 ／ためる 0.45 ／ながくためる 0.80秒 の4段階） | 「セットの時間・足を上げる速さ・足を上げて止める時間」の3要素で組み立てたい、という要望（2026-10-14）。「ため」は細かく使い分けられるよう1段階足した |
| 打者の「取りなおし」（`RESYNC_*`） | なし | 足を上げて長く止まる（ため 0.4秒以上）と、足を上げる速さのずれは3割しか打者に残らない。ためずに投げれば全部残る | 足を上げる速さを変えても、打者は足が上がって止まったところからタイミングを取りなおせる、という実際の感覚（2026-10-13 の指摘）。「クイック」「ゆっくり」は「すぐ」と組み合わせるとよく効く。`RESYNC_MAX` を 0 にすると、この効果はなくなる |
| 「ルール注意」を出す長さ（`MAX_TOP_HOLD`） | 0.3秒 | 0.9秒（設定で変更可） | 「ため」が主なずらしになったので、0.3秒のままだとカードを選ぶたびに注意が出る。足を上げて止める動きが反則になるかどうかは大会・連盟によるので、入門と設定画面の注意書きは残してある |
| ずらしの代償 | クイックすぎるとボールが増える／S3 が長いと長打 | 「クイック」「すぐ」（ため 0）はそれぞれボールが増える／ためが 0.3秒を超えると球の勢いが落ち始め、0.7秒で最大 | 「ため」の段階を増やしたのに合わせた |
| 同じパターン3球のボーナス | α が上がる | α に加えて、ばらつきも 0.8倍 | α だけだと、もう合っている打者には効果が出ないため |
| 牽制のやりすぎ・長すぎるセット | 「遅延の注意」 | 注意に加えてボールが1つ増える | 注意だけだと、やり得になるため |
| `PitchRecord.result` の `'steal'` | result の1つ | `runnerEvent`（`steal` / `caughtStealing`）に分けた。`pickoffSafe` / `stepOff` を足した | 盗塁は「見逃し」「空振り」などの投球結果と同時に起きるため |
| `Profile` | §8 のとおり | `stats`（統計）・`practice`（モード2の記録）・`version` を足した | 記録画面とバッジ用 |
| コースと高さ | コントロールは主題ではないので、ストライク率 70% の乱数 | **投げる場所を自分で選ぶ**。ストライクゾーン9マス＋まわりのボールゾーン2周・40マス（`src/sim/location.ts`。内側の1周はきわどいボール、外側の1周ははっきりしたボールで、打者が振る確率は 0.3倍）。ねらったマスに行くのは 70%（設定で変更可。クイック・すぐ・短いセットで下がる）、外れると隣のマス、まれに2マス先。図は投手から見た向きで、ゾーンの下の線は打者のひざ頭の下、上の線はベルトと胸のロゴの中間に合わせて描く | タイミングだけでなく、コースと高さも自分の意思で選びたい、という要望（2026-10-14） |
| 打者の情報 | タイプだけ | 打順（何番）・右打ち／左打ち・打ちそう度（●1〜5）・得意なコース（赤）と苦手なコース（青）。`src/game/stages.ts` の `b(4, 'boss', 'R')` で打順ごとに書く | 同上。得意コースはヒットが 1.25倍、苦手コースは 0.8倍。同じマスを続けると 1.25倍。高めは長打が増え、低めはゴロが増える。内角は差し込まれ、外角は泳ぎやすい（10ms）。リズムが主役で、コースはそれを少し助ける・台なしにする強さにしてある |
| 対戦・バッティング | なし | 1台を2人で使う対戦モード（`src/ui/screens/Versus.tsx`）。投手は3要素とコースを打者に見えないように選び、打者は投球を見て「振る！」を押す。押した時刻とボールが届く時刻の差が、そのままタイミングのずれになる（判定の幅は打者モデルと同じ：40ms 以内でジャスト）。投手をコンピューターにすると1人でバッティング練習ができる。記録は保存しない | 人間対人間で対戦したい、打つ方もタイミングを合わせる練習をしたい、という要望（2026-10-14）。通信対戦ではない（サーバーを使わない方針のため） |
| 牽制 | 走者の予想した足上げ時刻に近いほどアウト率が高い | 投手は**左投げ**として、牽制する塁とやり方を選ぶ：一塁（足を上げて／クイック）・二塁・三塁。アウトにできる確率の倍率は 一塁・足を上げて 1.6 ／一塁・クイック 1.0 ／二塁 0.75 ／三塁 0.5（`RUNNER.pickoffFactor`）。牽制すると、打者の予想が「ふつう」へ3割戻り、次の1球はばらつきが 1.4倍になる（待たされてリズムがくずれる）。対戦モードでも牽制できる（コンピューター投手もときどき牽制する） | 牽制でランナーを刺すだけでなく、打者のタイミングをずらす目的もある、という要望（2026-10-15）。左投手は一塁走者と向き合うので、足を上げてからの一塁牽制が投球と見分けにくい |
| 球速と球種 | リリースからホームまで 0.62秒 | ストレート 0.5秒（約100km/h）、スローボール 0.8秒。投手が球種を選ぶ。打者は予想していたボールの速さとの差の 45% がタイミングのずれになり（`BATTER_MODEL.SPEED_WEIGHT`）、スローを続けると慣れてストレートに振りおくれる。スローボールは当たると長打が 1.2倍、走者には走られやすい | 対戦モードで打者が見てから振っても間に合ってしまう、ストレートとスローボールを選びたい、という要望（2026-10-15） |
| 打者の見きわめ（対戦） | 横から見た投球だけ | 投球中、投手側から見たゾーン図に、ボールが奥から行き先のマスへ大きくなりながら飛んでくる | 横からだと内角・外角のストライク／ボールが判断できない、という指摘（2026-10-15） |
| 効果音（モード1） | — | 投球の動きに合わせて音を予約する：セット（グラブ）→ 足上げ → ためている間の心臓の音（0.28秒以上ためたとき）→ 腕を振る風の音 → ミット／金属バット → 観客。ボスの打席は太鼓、同じリズムが続くと注意の音 | 小6が面白がれて、ふざけすぎない音に、という要望（2026-10-14）。すべて Web Audio の合成で、音声ファイルは使っていない |
| 合図音の種類 | — | ピッ・ポン・パン／木の音／たいこ の3種類 | 「セット」とパターン名は端末の読み上げ（speechSynthesis）。読み上げは時刻が正確でないので、合図そのものには使っていない |
| 動画計測の撮影 | MediaRecorder | 端末のカメラアプリ（`<input type="file" capture>`）で撮って読み込む | iOS でアプリ内録画した動画はコマ送り（シーク）できないことがあるため。動画は端末内で再生するだけで、どこにも送らない |
| 1回の練習の上限 | 30回 | ホームからモード2に入ってから、ホームに戻るまでを「1回の練習」と数える | — |
| 盗塁・進塁 | — | アウトでは走者は進まない・併殺なし・単打は1つ、長打は2つ進む。盗塁を狙うのは「次の塁が空いている前の走者」1人 | コントロールや守備は主題ではないので単純にした |

## まだ実機で確かめていないこと（§12 の手動確認）

- 動画計測：実機のカメラで撮った動画のコマ送り
