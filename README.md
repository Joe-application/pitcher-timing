# タイミング外しピッチャー

少年野球（学童軟式・小6）の投手が、投球動作の「間（ま）」を変えて打者のタイミングをずらす練習をする Web アプリ。
姉妹アプリ「三塁コーチャー判断トレーナー」と同じ作り（Vite + React + TypeScript、ロジックと UI の分離、端末内保存、ログインなし）。

## 使い方

```bash
npm install
npm run dev      # http://localhost:5173 を開く
npm test         # ユニットテスト＋キャリブレーションテスト
npm run build    # dist/ に出力（PWA。一度開けばオフラインで動く）
```

## どこを直せばいいか

| 直したいもの | ファイル |
|---|---|
| 打者・走者の強さ、区間の目安、ルールの閾値などの数値 | `src/sim/constants.ts` |
| ステージ・「リベンジ」の場面（アウト・ランナー・点差・カウント・打順） | `src/game/stages.ts` |
| 子ども向けの文言・監督のひとこと・入門の文章 | `src/game/messages.ts` |
| 練習パターンのプリセット・組み立て練習の順番 | `src/practice/presets.ts` |
| 計測チャレンジの採点の幅 | `src/practice/score.ts` |

**`src/sim/constants.ts` の数値を変えたら、必ず `npm test` を通すこと。** キャリブレーションテスト（`src/sim/__tests__/calibration.test.ts`）が、仕様書 §10 の「体感として正しい挙動」を 3,000 打席のシミュレーションで確かめている。

## 構成

```
src/
  types.ts        データの形（仕様書 §8）
  sim/            シミュレーション。純粋関数のみ・UI に依存しない
    constants.ts  数値はすべてここ
    rng.ts        シード付き乱数（mulberry32）
    timing.ts     区間の計算、ボーク・ルール判定
    batter.ts     打者モデル（予想 → タイミング誤差 → 結果）
    runner.ts     走者・牽制モデル
    atBat.ts      打席・イニングの進行（1球ごとに 状態＋投球 → 新しい状態＋記録）
  game/           ステージ・文言・ランク／バッジ
  audio/cues.ts   合図音（Web Audio で AudioContext.currentTime に予約）と効果音
  practice/       モード2のロジック（計測・採点・プリセット）
  storage/        localStorage（キー `pitcherTiming:v1:<ニックネーム>`）と JSON 書き出し／読み込み
  ui/             画面
```

## キャリブレーションの結果（§10）

| # | 確かめること | 目標 | 結果 |
|---|---|---|---|
| 1 | 強打者に「ふつう」5球、4球目以降のジャスト率 | 60%以上 | 85% |
| 2 | 強打者に毎球「とまる」と「ため」を両方変える → 打ち取り率 | 55%以上 | 76% |
| 3 | まっすぐ待ちに1区間だけ変える → 打ち取り率 | 60%以上 | 72%（いつもふつうだと 47%） |
| 4 | S3 を0.6秒ためたときのジャスト時の長打率 | はっきり上がる | +23ポイント（強打者 40% → 63%） |
| 5 | 盗塁成功率：S1 いつも同じ／ばらつかせる | 70%以上／40%以下 | 89%／35% |
| 6 | ボス：でたらめ／直前と大きく変える → 打ち取り率 | 30%未満／50%以上 | 25%／88% |
| 7 | ボーク・二段モーション注意・遅延の判定 | 出る | ○ |
| 8 | 同じシードと入力で同じ結果 | 同じ | ○ |

ステージごとのクリア率（2,000 回のシミュレーション。投げ方の方針別）：

| ステージ | いつもふつう | でたらめ | 毎球2区間とも変える | 直前と大きく変える |
|---|---|---|---|---|
| 1 練習試合 | 58% | 97% | 98% | 100% |
| 2 地区大会 | 59% | 95% | 98% | 100% |
| 3 準決勝 | 48% | 95% | 98% | 99% |
| 4 決勝 | 25% | 80% | 89% | 98% |
| 5 リベンジ | 13% | 42% | 59% | 94% |

## 仕様書から変えた・足したところ

| 項目 | 仕様書 | 実装 | 理由 |
|---|---|---|---|
| 打者の「見て合わせられる幅」（`adjust`） | なし | 予想とのずれがこの幅（強打者 0.10秒、ボス 0.35秒）におさまれば、打者は合わせてしまう | 指数移動平均だけだと、ボスが「でたらめ」に投げても 57% 打ち取れてしまい、§10-6（30%未満）を満たせなかった。この幅を入れると「強打者は少しの変化なら合わせる」「ボスは直前と大きく変えないと崩れない」が自然に出る |
| 打者タイプの得意・苦手（`earlyGain` / `lateGain`） | 「せっかちは S3 のために弱い」「じっくり型はクイックに弱い」→ じっくり型は「すぐ」に弱い、に読み替え | 予想より遅い球／速い球に対するずれの倍率で表した | 1つの数字で直せるように |
| ボスは長いセットで力まない | じっくり型だけ力まない | ボスも力まない | 長く止まるだけでボスのばらつきが増え、でたらめでも打ち取れてしまうため |
| 「あしあげ」の速さ（S2） | カードで クイック／ふつう／ゆっくり | **どのパターンも同じ速さに固定**。カードは「とまる」（3段階）と「ため」（すぐ 0 ／ふつう 0.12 ／ためる 0.45 ／ながくためる 0.80秒 の4段階） | 足を上げる速さを変えても、打者は足が上がって止まったところからタイミングを取りなおせるので、ずらしにならない（2026-10-13、実際の感覚にもとづく指摘）。足を上げて止まっている時間で調整する |
| 「ルール注意」を出す長さ（`MAX_TOP_HOLD`） | 0.3秒 | 0.9秒（設定で変更可） | 「ため」が主なずらしになったので、0.3秒のままだとカードを選ぶたびに注意が出る。足を上げて止める動きが反則になるかどうかは大会・連盟によるので、入門と設定画面の注意書きは残してある |
| ずらしの代償 | クイックすぎるとボールが増える／S3 が長いと長打 | 「すぐ」（ため 0）だとボールが増える／ためが 0.3秒を超えると球の勢いが落ち始め、0.7秒で最大 | S2 を固定したのに合わせた |
| 同じパターン3球のボーナス | α が上がる | α に加えて、ばらつきも 0.8倍 | α だけだと、もう合っている打者には効果が出ないため |
| 牽制のやりすぎ・長すぎるセット | 「遅延の注意」 | 注意に加えてボールが1つ増える | 注意だけだと、やり得になるため |
| `PitchRecord.result` の `'steal'` | result の1つ | `runnerEvent`（`steal` / `caughtStealing`）に分けた。`pickoffSafe` / `stepOff` を足した | 盗塁は「見逃し」「空振り」などの投球結果と同時に起きるため |
| `Profile` | §8 のとおり | `stats`（統計）・`practice`（モード2の記録）・`version` を足した | 記録画面とバッジ用 |
| 合図音の種類 | — | ピッ・ポン・パン／木の音／たいこ の3種類 | 「セット」とパターン名は端末の読み上げ（speechSynthesis）。読み上げは時刻が正確でないので、合図そのものには使っていない |
| 動画計測の撮影 | MediaRecorder | 端末のカメラアプリ（`<input type="file" capture>`）で撮って読み込む | iOS でアプリ内録画した動画はコマ送り（シーク）できないことがあるため。動画は端末内で再生するだけで、どこにも送らない |
| 1回の練習の上限 | 30回 | ホームからモード2に入ってから、ホームに戻るまでを「1回の練習」と数える | — |
| 盗塁・進塁 | — | アウトでは走者は進まない・併殺なし・単打は1つ、長打は2つ進む。盗塁を狙うのは「次の塁が空いている前の走者」1人 | コントロールや守備は主題ではないので単純にした |

## まだ実機で確かめていないこと（§12 の手動確認）

- 合図音が耳で聞いてずれないか（iPhone / Android の実機、連続20回）
- 計測係の3タップの精度（ストップウォッチと比べて ±0.1秒以内か）
- モード2の画面が 2〜3m 離れて読めるか
- リアルタイム方式の押し心地（指を置く＝足上げ、はなす＝前へ）
- 動画計測：実機のカメラで撮った動画のコマ送り
